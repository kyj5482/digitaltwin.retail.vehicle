# F1 실시간 텔레메트리 조사 — 차량 트윈(V11) 반영 설계

> 2026-09-04 조사. 목표: F1 경기에서 차량 실시간 수집 데이터를 기반으로 판단·지시하는 방식을
> 조사하고, 이를 차량 트윈(v11-vin-twin.html)에 반영한다.
> 반영 결과: **모드 ③ 관제 (피트월)** — 타이밍 타워 · ATLAS식 다채널 라이브 · 레퍼런스 델타 ·
> 레이스 엔지니어 콜 · 몬테카를로 개입 전략.

## 1. 데이터 수집

- **센서 수**: 차량 1대당 약 **300개** (AWS F1 공식 페이지 확인). 파워유닛·기어박스·서스펜션·
  브레이크·타이어·공력 부위에 압력·온도·가속도·변위·토크 센서 분산 배치.
- **데이터양**: 초당 **110만+ 데이터 포인트**를 차 → 피트로 전송 (AWS 확인).
  레이스 주말 총량 팀별 약 1.5TB (팀 인터뷰 다수 인용, 근사치).
- **채널**: 속도·RPM·기어·스로틀·브레이크 압력·스티어링 각·GPS·3축 g·타이어 표면/내부
  온도·압력·브레이크 디스크 온도·ERS 배터리 SoC·MGU-K/H 에너지 흐름·연료 유량·서스펜션 변위 등.
- **전송 경로**: 차량 → 트랙사이드 안테나 → 피트월/개러지 → 전용 회선으로 본부 **원격 운영실**
  (Mercedes Race Support Room, McLaren Mission Control — 약 30명 내외, 근사치).
  원격 인력은 FIA 트랙사이드 인원 제한(58명)에 안 잡혀 본부 분석을 적극 활용.
- **표준 ECU**: 전 팀 McLaren Applied 표준 ECU(TAG-320 계열) 의무 사용. FIA도 동일 데이터로
  규정 준수 감시. **양방향 텔레메트리(피트→차량 원격 세팅)는 2003년 금지** — 모든 변경은
  드라이버가 직접 수행. 즉 "데이터는 내려받고, 조치는 지시로 전달"하는 구조.

## 2. 분석 도구

- **ATLAS** (Advanced Telemetry Linked Acquisition System, McLaren Applied): 사실상 표준.
  수백~수천 채널을 시간/거리축 **다중 트레이스 스택으로 중첩 표시**, 랩·스틴트·세션 간 비교.
- **레퍼런스 랩 델타**: 베스트 랩(또는 팀메이트)을 기준으로 현재 랩을 정렬해 구간별
  손실/이득(델타 트레이스)을 시각화 — 브레이킹 포인트·최저 속도·스로틀 재개 차이를 채널로 짚음.
- **히스토리컬 비교**: 70년치 히스토리 데이터(Amazon S3, AWS 확인)·동일 서킷 과거 세션과 대조.
- 팀별 자체 도구: 임계값 초과 채널 자동 하이라이트 경보 대시보드, 경쟁차 GPS 기반 상대 페이스 추정.

## 3. 의사결정 체계 — 역할과 지시

- **레이스 엔지니어 = 드라이버와 교신하는 유일한 목소리(single voice)**. 모든 부서 분석이
  이 사람을 거쳐 "지시"로 변환 — 채널 과부하 방지.
- 퍼포먼스 엔지니어(랩타임·밸런스), 타이어 엔지니어(온도·마모·수명 예측), 전략팀(트랙+본부).
- **대표 지시**: "Box, box"(피트인), PU/ERS 모드 변경, 브레이크 밸런스 조정,
  리프트 앤 코스트(연료·냉각), 타이어 관리 목표(델타 타깃), 오버테이크 버튼 허가.

## 4. 예측·전략 시뮬레이션

- **타이어 열화 모델**: 컴파운드별 랩타임 저하 곡선(선형+클리프)을 롱런 데이터로 피팅,
  레이스 중 실측으로 계수 실시간 갱신.
- **몬테카를로 레이스 시뮬레이션**: 세이프티카 확률·경쟁사 피트 타이밍·트래픽·피트스톱 편차를
  확률 변수로 **수천 시나리오 반복** → 기대 순위 최대 전략 선택. 레이스 전 수백만 회,
  레이스 중 **매 랩 재시뮬레이션** (규모 수치는 팀 인터뷰 기반 근사치).
- **언더컷/오버컷**: 신품 타이어 아웃랩 이득 vs 클리어 에어 이득을 갭·피트로스(~20-25초)로 계산.
- **이상 감지·고장 예측**: 채널의 정상 범위 이탈(온도 상승 추세·압력 강하·진동 변화)을
  임계값·패턴 기반 자동 감지 → 신뢰성 엔지니어가 초기 징후 단계에서 냉각 지시 또는 리타이어 결정.

## 6. 차량 트윈 반영 매핑 (V11 모드 ③ 관제)

| F1 실무 | 차량 트윈 반영 |
|---|---|
| 20대 타이밍 타워 (순위·갭) | **타이밍 타워** — 표본 8대를 AI 위험도 순 정렬, 기준차 대비 Δ12V·현재 차속 라이브 |
| ATLAS 다채널 트레이스 스택 | **라이브 채널 스택** — 차속·12V SoC·상태 스트립을 관제 시계에 맞춰 스트리밍 표시 |
| 레퍼런스 랩 델타 비교 | **기준차(Baseline VIN) 델타 트레이스** — 트립 채널 오버레이 + 생애 정렬 Δ12V 곡선 |
| 레이스 엔지니어 single voice | **엔지니어 콜 피드** — 모든 임계 이벤트가 단일 피드로 수렴, 콜 단위 "지시 전송" |
| "Box, box" 피트인 콜 | **BOX 콜 = 서비스 입고 예약** (위험도 임계 초과 시) |
| 리프트 앤 코스트 / 모드 변경 지시 | **보충 충전 지시 · 원격 진단 스캔 · OTA 배포 지시** |
| 타이어 열화 모델 실시간 갱신 | 12V 암전류/SoH 열화 궤적 — 실측 14일 기울기로 계수 추정 |
| 몬테카를로 전략 (매 랩 재시뮬) | **개입 전략 시뮬레이션** — 즉시 개입/14일 지연/미개입 × 24회 몬테카를로 × 60일 위험도 밴드 |
| 양방향 텔레메트리 금지 → 지시로 전달 | 트윈도 차량 원격 제어가 아닌 **지시(예약·충전·OTA 승인) 환류** — v10 프로젝트로 postMessage |
| 원격 운영실 (본부 분석) | 관제 모드 자체 = 본사 원격 운영실 관점 (딜러/고객 접점은 지시 수신자) |
