# 디지털 트윈 월드 컨설팅 리뷰 — V8·V9 진단과 V10 통합 설계

> 관점: 판매법인 운영 컨설턴트가 "이 트윈으로 실제 회사를 돌릴 수 있는가"를 심사한다.
> 도메인 근거는 `docs/oem-us-sales-process-research.md`(8사 프로세스 리서치), 기존 설계 근거는
> `docs/digital-twin-guide.md`·`docs/twin-insight-review.md`·`docs/ceo-1dau-review.md`.

## 1. 현재 자산 진단

### 1.1 V8 전략 시뮬레이션 트윈 — "미래를 바꾸는 손잡이"는 완성 단계
**강점**
- 실적 생성 수식 = 시뮬레이션 수식(가격탄력 2티어·adstock·재고 수렴) → "과거를 재현하는 모델로 미래를 생성" 원칙 성립. 컨설팅 관점에서 가장 어려운 신뢰 문제(모델이 과거도 못 맞추면 미래를 못 믿는다)를 구조로 해결
- 오늘의 브리핑·결정 스코어보드(커밋 밴드 추적)·AI 워게이밍 — CEO 의사결정 루프의 원형 보유
- 생산/판매 2층 씬 + 온톨로지 오버레이(iframe `?embed=1` 패턴) — V10 통합의 기술 패턴 확보

**한계**
- 시나리오를 **커밋한 뒤 실행으로 넘기는 통로가 없다**: 워게이밍 승자를 [적용]해도 그것이 다음 달 주문(ORD-1)·인센티브 프로그램·CSI 활동으로 이어지는 객체가 없음 — "결정은 있는데 업무가 없다"
- 레버 5종은 전사 수준 — 프로젝트(특정 차종×지역×조치) 단위 실행과 매핑되지 않음

### 1.2 V9 라이프사이클 트윈 — "회사가 지금 하는 일"은 완성 단계
**강점**
- 연간 캘린더 15개 활동 + 폐루프 씬 + 단계별 데이터 실체(8개 데이터셋) — 8사 공통 라이프사이클(리서치 §2)을 전 구간 커버
- 주문 로직(DoS Weight)이 Python↔JS 동일 수식으로 **트윈 안에서 실행** — "업무가 월드에서 수행된다"의 첫 사례

**한계**
- 활동은 보이지만 **의사결정 구조가 없다**: BP 승인·FOB 확정·리콜 결정·가격 개정은 8사 모두 사람이 검토·승인하는 게이트인데, 트윈에는 [진행중] 상태만 존재. 누가(사람/AI) 무엇을 검토 중인지, 위임 가능한 업무가 무엇인지 없음
- 활동들이 **목표와 연결되지 않는다**: ORD-1이 잘 돌아도 그것이 판매량·이익·만족도 어디에 기여하는지 화면에 없음 — 사용자가 지적한 "레거시 회사는 하나의 Goal로 진행되지 않는다" 문제가 트윈 안에도 남아 있음

### 1.3 온톨로지 (v0.10.0) — 선언은 충분, 활용은 탐색기에 갇힘
- 객체 27·링크 55·액션 32 타입 + `metrics`(retailQty/opProfit/daysSupply/csiExternal/csiInternal → agg_kpi·csi 바인딩)가 이미 선언되어 있고, 액션 타입에 `automation{before/after}` 필드까지 존재 — **HITL/AI 위임의 데이터 모델이 사실상 준비됨**
- 그러나 온톨로지는 탐색기(조회)에서만 쓰이고, 새 업무·프로젝트를 **구성(Compose)**하는 데 쓰이지 않음 — "온톨로지 기반 Top-down 구성"이 미구현

### 1.4 데이터 플랫폼 — 합격
- Upstream VIN 원장 + 공통 차원 큐브 + 상향식 BP + 내부 CSI 지수 체인은 실데이터 전환(P1)을 버틸 구조. 갭은 거버넌스 데이터(게이트·프로젝트 원장)의 부재뿐

## 2. 종합 판정

| 심사 항목 | V8+V9 현재 | 판정 |
|---|---|---|
| 라이프사이클 커버리지 (8사 공통 대비) | 15개 활동, 7단계 전 구간 | **양호** — 갭은 P1/P2 (딜러 컨센서스·캡티브 금융 등) |
| 업무가 트윈에서 "실행"되는가 | 주문 수식 1건만 실행, 나머지는 표시 | **미흡** — 게이트 수명주기 필요 |
| Human-in-the-loop / AI 위임 | 문서 개념만 존재 (가이드 P4 "담당자는 승인/수정만") | **부재** |
| 하나의 Goal 정렬 | KPI 타일은 있으나 목표 트리 없음 | **부재** |
| Top-down 프로젝트 구성·결과 리뷰 | csi_actions(OTA/FSC)가 유일한 "프로젝트" 원장 | **부분** — 일반화 필요 |
| 전략(V8)↔실행(V9) 연결 | 데이터 번들만 공유, 화면·객체 분리 | **부재** |

**결론: 부품은 다 있다. 없는 것은 "월드"다** — 목표에서 출발해 프로젝트로 분해되고,
프로젝트가 라이프사이클 업무의 게이트를 통과하며(사람 승인/AI 위임), 결과가 데이터로 쌓여
목표로 되돌아오는 **단일 폐루프 화면**. 이것이 V10이다.

## 3. V10 디지털 트윈 월드 — 설계

### 3.1 한 문장 정의
> **"판매량·영업이익·고객만족도 3대 목표 → KPI → 프로젝트 → 라이프사이클 업무(게이트)"의
> Top-down 트리가 살아 움직이는 월드.** 운영의 세부는 V9, 전략의 세부는 V8을 월드 안에서
> 소환(오버레이)하고, 월드 자체는 정렬(alignment)과 거버넌스를 담당한다.

### 3.2 화면 구조 (씬 기반 — 대시보드 아님)
- **중앙 씬 = 4티어 Top-down DAG** (Sugiyama 배치·직교 엣지, V9 규칙 계승)
  - T1 목표 3개(비콘): 판매량 / 영업이익 / 고객만족도 — 실적 vs BP 진행률·램프
  - T2 KPI 노드: 소매·도매·변동마진·인센티브·품질비용·Parts 이익·DS·CSI(외부/내부 4요소) — `ONTOLOGY.metrics`·agg 데이터 바인딩
  - T3 프로젝트 위성: 활성/완결 프로젝트가 기여 대상 KPI에 연결. 완결 사례 = OTA-2606-LUM(csi_actions 연동)
  - T4 라이프사이클 7단계 스테이션: 당월 게이트 칩(HITL 대기/AI 위임/자동) 부착 — 파티클은 승인된 게이트를 통과해 위로(실적 기여) 흐름
- **좌 레일 = 목표 스코어**: 3대 목표 연간 누적 vs BP + 미니 트렌드
- **우 패널 = 프로젝트 컴포저 + 게이트 큐**: ① 이번 달 검토 대기 게이트(승인/반려 실행) ② [+ 새 프로젝트] — 목표 노드 선택 → 템플릿 → 온톨로지 연계 객체 자동 연결 → 기대 임팩트(V8 탄력 수식) → 씬에 위성 추가
- **하단 타임라인**: 실적 32개월 Play (V9와 동일)
- **월드 소환**: 헤더 [운영 월드 V9]·[전략 월드 V8] → iframe 오버레이(V8의 온톨로지 오버레이 패턴 재사용, V8은 `#noBrief`로 진입)

### 3.3 신규 데이터 (거버넌스 원장 — SCHEMA §11)
| 데이터셋 | 내용 |
|---|---|
| `governance/ceo_tree.csv` | **CEO KPI 트리** — 3영역(재무 37·사업 35·지속경영 25) × 14 KPI(가중치) × 다운스트림 노드(앱폴더 계층·bind·lever). 미연결 노드 = 데이터 수집 프로젝트 대상 |
| `facility_energy/` (월 파티션) | 캠퍼스 동관/서관×층 전력 원장 — 전력사용량 leaf의 실체, HVAC 전략 레버(피크 +2°C·예냉 −2°C → 월 ≈ $10만 절감) |
| `governance/workflow_gates/` (월 파티션) | 활동별 게이트 상태 원장 — gate_type(hitl/ai_agent/auto)·담당·상태(자동실행/검토대기/승인/반려/예정) |
| `governance/ai_agents.csv` | AI 에이전트 레지스트리 (범위·위임 업무·정확도) |
| `governance/projects.csv` + `project_reviews/` | 프로젝트 마스터 + 월별 기대 vs 실적 리뷰 원장 |

게이트 상태는 규칙 기반(캘린더 창 내 위치 + 이벤트 원장)으로 Python·JS 동일 함수 — 주문 로직과 같은
"업무 로직이 트윈 안에서 실행" 패턴. 난수 없음(승인 이력은 결정적이어야 감사 가능).

### 3.4 HITL / AI 위임 원칙 (8사 리서치 근거)
| 게이트 | 유형 | 근거 |
|---|---|---|
| BP 승인·FOB 확정·트림믹스 확정 | **HITL** | 전사 손익 확약 — 8사 모두 경영 승인 |
| 리콜/캠페인 결정 | **HITL** (규제) | NHTSA 보고 의무 — 안전은 위임 불가 |
| Parts 가격 개정 | **HITL** | DN/Factory 균형 = 딜러 관계 의사결정 |
| 월 주문 배분 초안 | **AI 위임 → 사람 승인** | DoS Weight 수식 실행은 기계가 낫고, 확정은 사람 |
| VoC 분류·이슈 감지 | **AI 자동** | 대량·반복 — 이미 8사 자동화 영역 |
| 매체 예산 배분·캠페인 VIN 추출 | **AI 위임** | 규칙+최적화 — 사람은 예외만 |

### 3.5 이번 구현 범위(P0)와 이후
- **P0 (V10)**: 목표 트리 + 게이트 수명주기(승인/반려 실행 가능) + 프로젝트 컴포저(추가→연계 객체→기대 임팩트→월별 리뷰) + V8/V9 오버레이 소환 + 거버넌스 데이터 4종
- **P1**: V8 시나리오 커밋 → V10 프로젝트 자동 생성(전략→실행 통로), 딜러 컨센서스 게이트, 루프 리드타임 지표
- **P2**: Tier 2/3 마케팅·캡티브 금융·독립 디스트리뷰터 구간 (리서치 §3)


## 4. (개편 이력) CEO KPI 상위 체계 반영 — 2026-08-27

최초 V10의 목표 트리(판매량·영업이익·고객만족도 → KPI 10)는 실제 판매법인의 CEO KPI 체계보다
한 단계 낮았다. 실제 체계로 개편: **재무영역 37%**(ASP 5 · 경상이익률 5 · 합산손익 12 ·
합산손익률 15) / **사업영역 35%**(도매판매량 10 · 볼륨 SUV 육성 10 · 시장점유율 10 · 친환경
소매 5) / **지속경영영역 25%**(그린워싱 5 · Full SI 2.0 5 · CS 서비스/판매 각 3.5 · 보안 3 ·
브랜드트래커 5). 각 KPI 아래 다운스트림을 앱폴더로 계층 탐색하고(예: 경상이익률 → 오피스
관리비 → 전력사용량), leaf에서 전략 레버를 실행하면 업스트림으로 전파된다. 미연결 지표
(그린워싱·Full SI·보안 등)는 데이터 수집 프로젝트 신설로 확장 — "다운스트림에서 새 방안이
필요하면 프로젝트가 신설된다"의 구현. 온톨로지에 facility·energyMeter 객체와
adjustHvacSetpoint 액션을 추가(v0.11.0)해 최하위 데이터 실체까지 선언을 완결했다.

## 5. (개편 이력) 도메인 전략 월드 패턴 — 2026-08-27

V8이 판매·생산 도메인의 전략 월드이듯, **다운스트림 leaf마다 도메인 전용 전략 월드가
Seamless하게 소환·환류되는 패턴**을 에너지 도메인으로 첫 구현(`v10-energy-sim.html`):
전력사용량 드릴 [▶ 시뮬레이션] → 해시로 현재 레버 상태를 넘겨 소환 → 동관/서관 층별 씬 +
변경 가능한 레버 리스트(적용 범위·설정온도·예냉·조명 LED·ESS) → **다음 달(미래월) 비용
예측**(생성 모델과 동일 HVAC 곡선, SIMULATED) + 12개월 예측 차트 → [트윈 월드에 적용]이
postMessage로 V10 레버에 환류(운영 레버), 투자 레버(조명·ESS)는 프로젝트 신설로 환류.
확장 규칙: 새 도메인 월드 = ① 월드 등록(WORLDS) ② 해시 in / postMessage out 계약
③ 생성 모델 상수 미러 — 이 3가지만 지키면 어떤 leaf에도 전략 월드를 붙일 수 있다.

(갱신 2026-08-27) 도메인 전략 월드를 **오피스 관리비**로 확장 개편(`v10-opex-sim.html`):
V8 문법 그대로 — 좌측 KPI 리스트(전력사용량·임차/시설·소모품/기타) 클릭 → 씬 전환
(동관/서관 × 3층 × 구역 24, `office_zones` 임차 마스터 신설), KPI별 레버 리스트,
Play 타임라인(실적 32 + 미래 12개월 SIMULATED)과 향후 시뮬레이션 그래프.
V10 전력사용량 화면의 레버 패널은 제거 — 조정은 전략 월드에서, 적용 상태만 트윈 월드에 표시.
