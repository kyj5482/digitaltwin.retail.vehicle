# 01. 계층형 월드 아키텍처 — 레벨별 온톨로지 · 무플래시 전환

## 배경 — 프로토타입에서 확인된 문제

v10에서 전략 월드 ↔ 운영 월드의 최상위 전환은 문제가 없으나, **특정 링크로 타고 들어갈 때
제목줄이 (이전/기본 값으로) 보였다가 재로드되며 바뀌는 플래시**가 관찰되었다.

원인은 두 가지다.

1. **단일 iframe 재사용** — 소환 월드가 하나의 iframe을 공유해, 다른 문서로 바뀌는 동안
   이전 월드의 화면(제목줄 포함)이 새 문서 로드 완료까지 남아 보인다.
2. **딥링크 상태 후적용** — 소환된 월드가 기본 뷰(기본 제목줄)를 먼저 렌더한 뒤
   URL 해시(`#focus:` `#act:`)를 읽어 다시 렌더한다. 첫 페인트와 상태 적용 사이가 보인다.

프로토타입에는 임시 규격을 적용했다 (실개발에서는 아래 정식 규격으로 대체):
- `v10-twin-world.html` — iframe `loading` 클래스: 다른 문서로 소환 시 load 완료까지 숨김.
- `v7-ontology-explorer.html` — `dlVeil` 베일: 해시 상태를 선적용한 프레임 이후에만 페인트 노출.

## 요구사항 1 — 월드는 계층(레벨) 트리로 등록한다

월드를 개별 HTML 문서의 평면 집합이 아니라, **레벨 트리를 가진 레지스트리**로 선언한다.

| 레벨 | 월드 | 온톨로지 스코프 (해당 레벨의 데이터 계약) |
|---|---|---|
| L0 회사 | 트윈 월드 (관계뷰 메인 씬) | 법인·목표 영역·CEO KPI 트리 — 월 집계 스냅샷 |
| L1 도메인 | 전략 월드(시뮬레이션·관리비·차량 데이터) · 운영 월드(라이프사이클) | 도메인 KPI·레버·시나리오 — 도메인 마트 |
| L2 부문 | 9부문 운영 월드 (워크플로우 스텝·게이트) | 워크플로우·승인 게이트·프로젝트 — 실행 원장 |
| L3 데이터 | 온톨로지 액션의 데이터 뷰 (지도·보드·목록) | 인스턴스(VIN·주문·클레임 …) — 상세 마트 |

**구현 상태 (2026-08)**: 월드 레지스트리는 정식 산출물로 구현되었다 —
정본 `development/world-registry.json`(조직 org.hq/siblings N개 · 9부문 depts의
스텝×onto 매핑 · 소환 월드 카탈로그 worlds)을 `build-entity.js`가 entity-profile 표기와
병합·검증(부문 KPI↔ceo_tree, onto↔시멘틱 정본)해 `prototypes/world-registry.js`
(`window.WORLD_REGISTRY`)로 생성하고, v10은 조직·부문·소환 월드 구조를 전부 이
레지스트리에서 파생한다 (코드 하드코딩 금지 — 회귀 W19·C20이 검증). 형제 법인 수 제한(2개)은
제거되었다. 아래 스키마는 후속 레벨 트리 확장(route·parent) 예시다.

월드 레지스트리 스키마 (레벨 트리 확장 예시):

```json
{
  "id": "dept-sales",
  "level": 2,
  "parent": "world-ops",
  "title": "◎ 운영 월드 — 판매",
  "route": "/ops/dept/DEPT-SLS",
  "ontology": { "objects": ["approvalGate", "workflowStep"], "actions": ["ACT-ORDER-DOS"] },
  "data": { "grain": "gate×month", "sources": ["governance/workflow_gates"] }
}
```

- 제목(title)·브레드크럼은 레지스트리에서 파생한다 — 월드가 로드된 뒤 자기 제목을 다시 쓰는
  방식 금지 (제목 플래시의 구조적 차단).
- 하위 월드 진입은 반드시 상위 월드의 노드(온톨로지 객체)를 경유한다 — 임의 점프 없음.

## 요구사항 2 — 데이터도 레벨마다 온톨로지로 구성한다

- 각 레벨은 **자기 레벨의 온톨로지 서브그래프**(객체·링크·액션 타입)와 그레인이 명시된
  데이터 계약을 가진다. 상위 레벨은 하위의 **집계만** 알고, 드릴 시 하위 계약의 데이터를 로드한다.
- 인스턴스 조회는 온톨로지 바인딩(`datasource.path`)을 통해서만 한다 — 화면이 마트 테이블을
  직접 아는 것 금지. (상세: `02-data-ontology.md`)
- 레벨 간 이동 시 필요한 컨텍스트(커서 월, 레버 상태, 포커스 노드)는 라우트에 직렬화한다.

## 요구사항 3 — 상태 선적용 (무플래시) 라우팅

- 라우트(URL)가 상태의 단일 출처다: `월드 경로 + 포커스 + 시간 커서 + 레버`가 URL로 재현된다.
- 월드는 **첫 페인트 전에** 라우트 상태를 모두 적용한다. 기본 뷰를 그린 뒤 재적용 금지.
- 로드/전환 중에는 스켈레톤 또는 베일이 화면을 덮는다 — 이전 월드나 기본 제목줄이
  한 프레임도 보여서는 안 된다.
- 뒤로가기 = 한 레벨 위로 (브라우저 히스토리와 월드 트리가 일치).
