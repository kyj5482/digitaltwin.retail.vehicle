## V7 핵심 (전략 시뮬레이션 트윈)

- **오늘의 브리핑 (CEO 1-DAU 첫 화면)**: 접속 즉시 "오늘의 3가지"(케파 병목 조기 경보 · 지역×사양 수요 괴리 TOP1 · BP 궤도 갭) 푸시 + **결정 스코어보드**(시나리오 ☆커밋 → 현 궤도가 커밋 밴드 안인지 KPI별 월 판정). 설계 근거 `docs/ceo-1dau-review.md`
- **AI 워게이밍 (전략 레버 패널 ⚔ 버튼)**: 후보 = 베이스라인 + 현재 검토안 + **등록 시나리오** + 현재 레버 주변 변주 + 전략 전형(수익/성장/긴축/공세 등 10종) — 최대 32개 × 수요 충격 ±10% 일괄 시뮬 → 목표함수(이익/판매/균형) 랭킹 + 강건성 n/3 → [적용]=레버 반영, [등록]=시나리오 목록 추가(커밋·오버레이 연계)
- **전략 레버 5종** (가격 · 인센티브 · 마케팅 · 목표 재고 DS · EV 증산) — 변경 즉시 미래 16개월 재생성
- **시나리오 등록·다중 비교**: 레버 조합을 이름 붙여 등록 → 선택된 시나리오가 모두 차트에 오버레이, 행별 표시 토글·적용·삭제 (프리셋 카드 S1~S5는 빠른 시작용, `docs/v7-strategy-scenarios.md`)
- **상세 분석 모드**: KPI 레일 유지 + 타일 클릭으로 지표 전환, 동일 48개월 x축 + Play 커서 연동, 차종·MY·트림·엔진·구동(AWD/FWD)·색상 **다중 선택** 필터 × 지역별 트렌드 + 최근 3개월 vs 이전 12개월 변화율 + **자동 탐지 TOP 6 (현재 필터 기준 재계산)** — data/retail_sales_attr·retail_color_mix와 동일 믹스 모델
- **필터 = KPI 크로스 필터링**: 필터가 걸리면 KPI 타일도 슬라이스 값으로 전환(배너 표시, 닫으면 복귀). 데이터 원리(SCHEMA.md §0·§9): **Upstream은 VIN 원장 + 차량 마스터**(필터 속성 정본), Downstream은 조인 group-by로 만든 **공통 차원 통합 KPI 큐브**(agg_kpi) — 손익도 VIN 단위 도매 기반이라 근사가 아닌 집계, **BP는 같은 믹스 모델로 상향식 생성**(agg_kpi_bp)이라 어떤 필터에도 BP 대비 성립
- **고객만족도 이원화**: 외부 공시 CSI(외부기관 데이터) + **내부 100점 지수**(품질 클레임·커넥티드·서비스 예약·인도 — 내부 원장과 1:1 연계) + 개선 활동 원장(예: 커넥티드 SW 결함 → OTA 1만대 시정 → 클레임 8.5→0.4 소멸 → 계산식으로 점수 회복). 고객·CSI 드릴 패널에서 확인
- **차트 상호작용**: 휠=Y축 줌, 세로 드래그=Y축 이동, 호버 툴팁, [Y축 초기화] 버튼 — 메인·분석 차트 공통
- **IBCS 라인 문법**: 실적=실선 · BP=회색 세선 · 시나리오=파선 + 호라이즌 비례 팬차트 밴드
- **영업이익 임팩트 워터폴**: BP → 베이스라인 갭 → 레버별 기여 분해 → 시나리오
- **2.5D 아이소메트릭 씬**: 공장·항만·딜러 지역 프리즘, 파티클 유량, 재고 기둥(높이=DS, 색=밴드),
  고스트 기둥=베이스라인, 케파 병목 시 공장 적색 경고
- 월별 Play 타임라인: NOW를 넘으면 씬·차트가 시나리오 생성 구간으로 전환 (SIMULATED 워터마크)
- 집계 → 지역/공장 드릴 → VIN 이벤트 체인까지 3단 추적 유지

시뮬레이션 수식과 실적 데이터 생성 수식이 **동일 구조**(가격탄력 −1.6/−4.0 2티어, adstock 0.5,
로그 체감 마케팅, 재고 수렴 0.5)라서 "과거를 재현하는 모델로 미래를 생성한다"는 원칙이 성립한다.

## V7 온톨로지 탐색기

시뮬레이션 트윈이 다루는 비즈니스 세계를 **온톨로지(객체 타입 25 · 링크 타입 42 · 액션 타입 17)**로
명시하고 탐색하는 보조 도구. 4개 탭 — ① 온톨로지 그래프(타입 수준 관계망, Cytoscape —
밸류체인 가로 배치 ↔ 아이소메트릭 3층 레이어 스택(기준 정보→운영→고객·품질) 토글), ② 객체 탐색(v7-data.js 기반 인스턴스
480개·링크 996개를 타입→객체→연결 순으로 드릴), ③ 액션·수명주기(차량 수명주기
생산→운송→항만→배분→도매→소매→운행 7단계 + G1~G4 게이트 검사 전이, 액션 타입 카탈로그),
④ 데이터 파이프라인(데이터 엔지니어 뷰 — parquet 마트→온톨로지 변환 흐름도, 마트↔객체 바인딩
테이블과 빌드 순서 DAG를 온톨로지 선언에서 자동 생성, 증분·품질 게이트·DuckDB 변환 예시).
정의는 `v7-ontology.js`, 인스턴스 빌드는 `v7-ontology-instances.js`가 담당한다.

## 프로토타입 실행

로컬 서버(Node, 외부 의존성 없음)로 전 버전을 서비스한다. 인덱스 페이지에서 버전을 선택:

```bash
node server.js                        # http://localhost:8080/ → 버전 목록
node server.js --port 3000            # 포트 변경
node server.js --prefix /digitaltwin  # CloudFront 프리픽스 재현 → http://localhost:8080/digitaltwin/
```

CloudFront 배포 시 URI 앞의 프리픽스가 그대로 유지되므로, **모든 리소스·API 호출은 상대
경로**를 사용한다(절대 경로 `/...` 금지). `--prefix` 모드는 프리픽스 없는 요청을 404로
돌려 절대 경로 호출을 로컬에서 즉시 잡아낸다. 단일 HTML이라 브라우저에서 직접 열어도
된다 (v7은 `v7-data.js`가 같은 폴더에 있어야 함).
