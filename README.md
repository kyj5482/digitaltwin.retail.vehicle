## V10 핵심 (디지털 트윈 월드 — 회사 목표 관계뷰·부문 워크플로우 폐루프)

8사 프로세스 리서치(`docs/oem-us-sales-process-research.md`)와 컨설팅 진단
(`docs/twin-world-consulting-review.md`)에 근거해 V8(전략)·V9(운영)를 단일 월드로 통합:

- **회사 목표 관계뷰 (메인 씬)**: 온톨로지 관계뷰 문법 — 업스트림 `북미권역본부`(산하
  캐나다·멕시코 법인은 planned 점선) 아래 루트 `미국판매법인`, 그 아래 재무·사업·지속경영·운영
  4영역. 노드 클릭 = 그 노드가 중심이 되고 **업스트림(상향 롤업)과 다운스트림(실행·데이터)**
  이 카드로 펼쳐져 계속 이동, 씬 상단 브레드크럼·ESC(상위)로 복귀. 씬 뷰박스는 컨테이너
  종횡비에 맞춰 동적 계산되어 레터박스 없이 세로 영역을 꽉 채운다. 별도 드릴 패널 없음 —
  상세는 우측 패널, 시계열은 하단 그래프가 담당한다. 포커스 옆에는 **실제 구현된 운영/전략
  월드가 있는 객체에만** 바로가기 칩이 뜬다(법인=V9·V8, 부문/스텝=부문 운영 월드,
  관리비/전력=관리비 전략 월드 — 객체별 월드가 구축되는 대로 추가, 헤더 월드 버튼 대체).
  자주 가는 뷰는 **Quick Link**(★ 저장, localStorage 유지, 좌 레일 회사 목표 아래)로 바로 진입
- **인트로 시네마틱**: 첫 진입 시 6씬 · 약 36초의 모션그래픽 인트로가 자동 재생된다
  (쇼츠식 분절 프로그레스 · 클릭 = 다음 · ESC = 건너뛰기 · 헤더 [✦ 인트로]로 재생) —
  관계망·폐루프·학습 예측·전략 레버까지, 디지털 트윈 월드가 무엇이고 회사가 어디까지
  갈 수 있는지 상상하게 하는 오프닝. `localStorage`로 1회만 자동 재생
- **학습 기반 예측 (FORECAST · 학습 v0)**: 포커스 그래프가 32개월 실적을 학습(시즌 지수
  + 선형 추세)해 **미래 12개월을 점선 FORECAST**로 그린다 — NOW 분리선·예측 배경·+12M
  예측값. 예측 모델은 온톨로지 `mlModel` 레지스트리(ML-KPI-FCST-V0)로 선언되며, 가상
  데이터 주입(레버)은 전략 월드에서 미래를 재생성한다 — v0 시즌+추세 → v1 드라이버 회귀
  → v2 시나리오 생성의 로드맵
- **차량 데이터 전략 월드 (`v10-vehicle-sim.html`, IT)**: 주행(Trip)·DTC·기능 사용(HDA·
  트레일러 모드·FOTA·커넥티드 옵트인) 신호의 `feature_usage/` 마트(월×차종, **DTC는 내부
  CSI가 쓰는 claim_rate와 동일 소스에서 파생** — 인과가 데이터에 실재). 차종×신호 히트맵
  + **KPI 드라이버 발굴 보드**(신호×KPI 피어슨 상관 랭킹 — LUM DTC↔커넥티드 지수 r≈−0.98,
  AUR DTC↔품질 지수 r≈−0.95가 레버 후보로 발굴됨) + 레버 3종(FOTA 캠페인·HDA 온보딩·조기
  경보 — 가상 데이터 주입)으로 12개월 신호·KPI 재생성 → [트윈 월드에 적용] = 데이터
  프로젝트 환류. 온톨로지에 `featureUsageEvent`(bound)·`mlModel`(derived) + 학습 링크
  4종 + 액션 3종(적재·학습·드라이버 발굴)을 선언 — **마트가 온톨로지에 bound여야 학습
  가능하다**는 확장 원칙
- **차량 트윈 (`v11-vin-twin.html`, 서비스·품질·KPI-CSIS에서 소환)**: **하나의 서비스 —
  고객 만족(서비스) 개선.** 진입점은 홈 KPI 트리: 최상위 내부 CSI(결과) ← 팀별 하위 KPI
  6종(선행) — 딜러 서비스(재고 12V 건전율·장기 재고 90일+ 비중), 품질팀(DTC/1k·시정
  OTA-2606 적용률), 서비스팀(12V 방전/1k·사전 진단 조치 전환율). 각 KPI는 목표·근거
  데이터·문제 차량·조치를 가지며 **① KPI 확인 → ② 데이터 확인(KPI 상세: 카테고리 롤업·목표
  판정·OTA 전후 Δ) → ③ 문제 VIN 드릴 → ④ 조치 등록(환류) → ⑤ 재검증** 폐루프로 닫힌다.
  VIN 트윈은 그 드릴 종착점 — 한 대의 차량을
  생산→G1 PDI→운송(G2 VPC)→딜러 인수(G3)→재고→G4 PDS→판매→서비스까지 시계열로 트윈.
  게이트마다 KDS 진단(12V SoC·SoH·DTC·판정), 이벤트 사이에 실차 수집 데이터(12V SoC 일
  시계열·누적 주행거리·DTC 발생), **트립(시동 ON~OFF) 선택 시 차속·12V·HDA·Terrain·경고등
  10초/틱 재생** — 가상 환경 정비 수준. **상태 리플레이 (홀로 트윈 콕핏)**: 주행
  연출(도로·바퀴·벨트) 없이 그 시점의 차량 "상태"만 재생한다 — 중앙에 발광 원형 패드 위
  3/4 와이어프레임 홀로그램 차량(부유·스캔라인·경고등 원인 부품 적색 펄스), 둘레에 데이터
  패널: 상단 차속·12V 차트(진행 reveal), 좌열 부품 클로즈업(12V X-ray·HDA 센서 — 리더로
  차량 부위 앵커)·상태 트랙·이벤트 로그, 우열 루트 미니맵(시드 결정론 맨해튼 루트 + 진행
  마커)·차대 상태도(탑뷰 BATT/TCU/PE 하이라이트)·시점 상태 타일 6종 + 하단 클러스터
  HUD(속도계·12V·텔테일·스크러버). 데이터 시계는 배속(×10/20/40) 압축. 표본 8대(판매 전 12V 방전·커넥티드 DTC→OTA·FSC
  수리·견인 헤비·HDA 헤비·운송 손상·장기 재고·기준 차량)는 시드 PRNG 결정론 합성(L0 번들
  비대화 없이 L3 지연 생성 — v8 vinChain 패턴). 플릿 모드는 차종·MY·엔진 카테고리로 12V
  방전/1k·DTC/1k·CSI 서비스·OTA 적용률 KPI를 정의하고 **S/W(OTA-2606) 배포 전 3개월 vs
  후 변화량**으로 달성을 검증(집계→VIN 드릴다운). AI 사전 진단(위험도·근거·권고)이 서비스
  예약·OTA 배포로 이어지고 `v11-svc-project` postMessage로 트윈 월드 프로젝트에 환류 —
  "고객 맞춤 AI 의사(사전 진단→예약/OTA)" 메인 서비스의 프로토타입. **관제(피트월) 모드**:
  F1 레이스 엔지니어링 방식 조사(`docs/f1-telemetry-research.md` — 차량당 ~300 센서·초당
  110만+ 포인트, ATLAS 다채널·레퍼런스 랩 델타, single voice 지시, 몬테카를로 전략)를
  반영한 실시간 관제 — 타이밍 타워(위험도 순 플릿 라이브), ATLAS식 채널 스택(차속·12V +
  기준차 레퍼런스 오버레이·Δ12V 델타 바·생애 정렬 델타), 레이스 엔지니어 콜 피드(임계
  이벤트→BOX 콜·보충 충전·원격 진단·OTA "지시 전송" 환류 — 양방향 원격 제어 금지 원칙과
  동형), 개입 전략 몬테카를로(즉시/14일 지연/미개입 × 24회 × 60일 위험도 밴드 — 언더컷 판단)
- **포커스 그래프 + 우 패널 (모두 Play 연동)**: 씬 아래 그래프 영역이 포커스 대상의 32개월

## V7 핵심 (전략 시뮬레이션 트윈)

- **오늘의 브리핑 (CEO 1-DAU 첫 화면)**: 접속 즉시 "오늘의 3가지"(케파 병목 조기 경보 · 지역×사양 수요 괴리 TOP1 · BP 궤도 갭) 푸시 + **결정 스코어보드**(시나리오 ☆커밋 → 현 궤도가 커밋 밴드 안인지 KPI별 월 판정). 설계 근거 `docs/ceo-1dau-review.md`

- **전략 레버 5종** (가격 · 인센티브 · 마케팅 · 목표 재고 DS · EV 증산) — 변경 즉시 미래 16개월 재생성
- **시나리오 등록·다중 비교**: 레버 조합을 이름 붙여 등록 → 선택된 시나리오가 모두 차트에 오버레이, 행별 표시 토글·적용·삭제 (프리셋 카드 S1~S5는 빠른 시작용, `docs/v7-strategy-scenarios.md`)
- **상세 분석 모드**: KPI 레일 유지 + 타일 클릭으로 지표 전환, 동일 48개월 x축 + Play 커서 연동, 차종·MY·트림·엔진·구동(AWD/FWD)·색상 **다중 선택** 필터 × 지역별 트렌드 + 최근 3개월 vs 이전 12개월 변화율 + **자동 탐지 TOP 6 (현재 필터 기준 재계산)** — data/retail_sales_attr·retail_color_mix와 동일 믹스 모델
- **필터 = KPI 크로스 필터링**: 필터가 걸리면 KPI 타일도 슬라이스 값으로 전환(배너 표시, 닫으면 복귀). 데이터 원리(SCHEMA.md §0·§9): **Upstream은 VIN 원장 + 차량 마스터**(필터 속성 정본), Downstream은 조인 group-by로 만든 **공통 차원 통합 KPI 큐브**(agg_kpi) — 손익도 VIN 단위 도매 기반이라 근사가 아닌 집계, **BP는 같은 믹스 모델로 상향식 생성**(agg_kpi_bp)이라 어떤 필터에도 BP 대비 성립
- **고객만족도 이원화**: 외부 공시 CSI(외부기관 데이터) + **내부 100점 지수**(품질 클레임·커넥티드·서비스 예약·인도 — 내부 원장과 1:1 연계) + 개선 활동 원장(예: 커넥티드 SW 결함 → OTA 1만대 시정 → 클레임 8.5→0.4 소멸 → 계산식으로 점수 회복). 고객·CSI 드릴 패널에서 확인
- **차트 상호작용**: 휠=Y축 줌, 세로 드래그=Y축 이동, 호버 툴팁, [Y축 초기화] 버튼 — 메인·분석 차트 공통
- **IBCS 라인 문법**: 실적=실선 · BP=회색 세선 · 시나리오=파선 + 호라이즌 비례 팬차트 밴드
- **영업이익 임팩트 워터폴**: BP → 베이스라인 갭 → 레버별 기여 분해 → 시나리오
- **2.5D 아이소메트릭 씬**: 공장·항만·딜러 지역 프리즘, 파티클 유량, 재고 기둥(높이=DS, 색=밴드),
  고스트 기둥=베이스라인, 케파 병목 시 공장 적색 경고
- 월별 Play 타임라인: NOW를 넘으면 씬·차트가 시나리오 생성 구간으로 전환 (SIMULATED 워터마크)
- 집계 → 지역/공장 드릴 → VIN 이벤트 체인까지 3단 추적 유지

시뮬레이션 수식과 실적 데이터 생성 수식이 **동일 구조**(가격탄력 −1.6/−4.0 2티어, adstock 0.5,
로그 체감 마케팅, 재고 수렴 0.5)라서 "과거를 재현하는 모델로 미래를 생성한다"는 원칙이 성립한다.

## V7 온톨로지 탐색기

시뮬레이션 트윈이 다루는 비즈니스 세계를 **온톨로지(객체 타입 29 · 링크 타입 57 · 액션 타입 33)**로
명시하고 탐색하는 보조 도구. 4개 탭 — ① 온톨로지 그래프(타입 수준 관계망, Cytoscape —
밸류체인 가로 배치 ↔ 아이소메트릭 3층 레이어 스택(기준 정보→운영→고객·품질) 토글), ② 객체 탐색(v7-data.js 기반 인스턴스
480개·링크 996개를 타입→객체→연결 순으로 드릴), ③ 액션·수명주기(차량 수명주기
생산→운송→항만→배분→도매→소매→운행 7단계 + G1~G4 게이트 검사 전이, 액션 타입 카탈로그),
④ 데이터 파이프라인(데이터 엔지니어 뷰 — parquet 마트→온톨로지 변환 흐름도, 마트↔객체 바인딩
테이블과 빌드 순서 DAG를 온톨로지 선언에서 자동 생성, 증분·품질 게이트·DuckDB 변환 예시).
정의는 `v7-ontology.js`, 인스턴스 빌드는 `v7-ontology-instances.js`가 담당한다.

## 프로토타입 실행

로컬 서버(Node, 외부 의존성 없음)로 전 버전을 서비스한다. 인덱스 페이지에서 버전을 선택:

```bash
node server.js                        # http://localhost:8080/ → 버전 목록
node server.js --port 3000            # 포트 변경
node server.js --prefix /digitaltwin  # CloudFront 프리픽스 재현 → http://localhost:8080/digitaltwin/
```

CloudFront 배포 시 URI 앞의 프리픽스가 그대로 유지되므로, **모든 리소스·API 호출은 상대
경로**를 사용한다(절대 경로 `/...` 금지). `--prefix` 모드는 프리픽스 없는 요청을 404로
돌려 절대 경로 호출을 로컬에서 즉시 잡아낸다. 단일 HTML이라 브라우저에서 직접 열어도
된다 (v7은 `v7-data.js`가 같은 폴더에 있어야 함).
